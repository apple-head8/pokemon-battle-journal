# 対戦ノート

`start.cmd` をダブルクリックすると起動します。Node.js 20.12以上が必要です。
新しくクローンした場合は、`battle-log` フォルダで `npm ci` と `npm run build` を先に実行してください。
画面: http://127.0.0.1:4318

- サーバーは背景で起動します。PC再起動後は同じ `start.cmd` で再開できます。
- 保存先: `data/battles.json`。直前の保存状態は `data/battles.json.bak` に残ります。
- バックアップボタンで全対戦のJSON、CSV出力で絞り込み中の対戦を出力できます。
- JSON読み込みは追加方式。同じIDの記録は上書きしません。
- 勝率は勝ち数÷記録数（引き分けを含む）。積む機会の集計は「作れた」「作れなかった」の回答のみ対象です。
- 入力途中の内容は同じブラウザの下書きに保存。確定した記録はPCのファイルに保存します。
- 外部公開やクラウド同期は行いません。履歴はこのフォルダ内のファイルです。
- 構築名は自由入力。技・配分を変更したら名前を変えて比較してください。
- 過去11戦は構築・選出に不明な点があるため、自動で登録していません。

## パーティー管理

「パーティー管理」から専用ページ `/parties` を開いて名前と6匹を登録します。
持ち物は1行入力、性格は選択、配分はH/A/B/C/D/Sの数値入力、技は4枠の入力です。
SPは各0〜32・合計66以下。名前以外は後から入力できます。過去の型メモは読み取り専用で保持します。
↑↓で並び替えると、選出のセレクトボックスにも同じ順番で反映されます。
新規登録・編集・複製ができます。構築を比較するときは複製して別名を付けてください。
新しく保存する対戦には、その時点のパーティー情報も残るので、後の編集で過去の構築が書き換わることはありません。
既存の対戦履歴はそのまま保持します。JSONバックアップにはパーティーも含まれます。

## Git

アプリのコードとテストを、この作業フォルダのGitリポジトリで管理しています。
対戦履歴・登録パーティーなどの個人データ（data/）はGit管理対象外です。画面のバックアップボタンで保管してください。
コードはローカルGitとGitHubの非公開リポジトリ `apple-head8/pokemon-battle-journal` で管理しています。

## 没にする・ダークモード

管理ページの「没にする」は選出候補から除外する操作です。履歴や型は削除しません。
「没にした構築」から選び、「復帰させる」で使用中に戻せます。
没にしたパーティーの過去の対戦は引き続き閲覧・編集できます。
右上のダーク/ライト切り替えは両ページ共通で、同じブラウザに設定を保存します。初回はOSの設定に従います。

## 技術構成

- パーティー管理: React（JavaScript / JSX）
- ビルド: Vite。`npm run build` で `public/build` に生成
- 対戦記録画面: HTML / CSS / JavaScript（既存の画面を維持）
- 保存API: Node.js のHTTPサーバー、JSONファイル保存
- `npm test`: 旧データ互換、構築保存、SP制約、没/復帰、履歴保持のテスト

開発時はReactの変更後に `npm run build`、サーバーの変更後に再起動してください。

テスト: `node --test server.test.js`

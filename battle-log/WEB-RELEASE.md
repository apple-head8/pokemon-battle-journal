# 公開・保存設計

## GitHub Pagesへの配布

公開対象は `battle-log/web-dist/` の中身だけです。対戦データ、ローカルAPI、Git履歴、node_modulesは含めません。

`.github/workflows/deploy-pages.yml` は手動実行用です。Node.js 24で依存監査、Webビルド、テストを行い、成功した配信物をPagesへデプロイします。ActionsはコミットIDで固定しています。

1. GitHub Pagesを利用できるリポジトリを用意し、Settings → Pages → SourceをGitHub Actionsにします。
2. コードをpushし、Actionsの「Deploy Rotom Log to GitHub Pages」を実行します。
3. デプロイ完了後、公開URLで初期設定・保存・再読込・ファイル再開を確認します。

2026-10-18にリポジトリを公開へ変更し、GitHub ActionsによるPages配信を有効化しました。公開先は https://apple-head8.github.io/pokemon-battle-journal/ です。更新時は同じワークフローを手動実行します。

サブパス配信は `WEB_BASE_PATH=/repository-name/` を指定します。ワークフローではリポジトリ名から設定します。独自ドメインのルートなら `/` を指定してください。

```sh
npm ci
npm run build:web
npm test
npm audit --audit-level=high
npm run preview:web
```

プレビューは4319番、ローカル版は4318番です。保存領域は別で、個人データを自動コピーしません。公開URLへの移行時は保存済みJSONを開き直します。

## 保存設計

Web版は静的HTML・CSS・JavaScriptのみです。認証や記録保存サーバー、AIへの通信はありません。

- PCの対応ブラウザではFile System Access APIで指定JSONへ保存します。
- IndexedDBに記録、リビジョン、ファイルハンドル、前回保存内容を保持します。対戦の下書きはlocalStorageです。
- 保存は検証 → Web Locksによる直列化 → ブラウザへ退避 → ファイル内容の照合 → 書き込み・close → 保存済み状態の更新、の順です。
- 許可拒否・書き込み失敗は成功扱いにしません。再保存するまで次の変更を止め、二重登録を防ぎます。
- 外部変更や古いタブからの更新は拒否します。別ブラウザ・OSアプリとの排他は保証できません。
- 別の記録ファイルを開く操作は切り替えです。JSON読み込みによる追加とは異なります。新しい保存先に空でないファイルを指定すると書き込みません。
- ブラウザ保存モードでは手動でのJSON出力が必要です。自動同期・暗号化・PWAによるオフライン起動は提供しません。

ローカル版は `data/battles.json` を一時ファイルから置換し、直前の版を `.bak`、直近30世代を `data/backups/` に保持します。これらはWeb版の機能ではありません。

## セキュリティ対策と限界

- JSONは5MB・1万対戦・千構築まで。全件の形式・ID・入力範囲を検証し、未知のフィールドを除外します。
- 入力文字列はReactの通常描画またはtextContentで表示します。CSVは数式として解釈される先頭文字を処理します。
- 外部CDN・外部フォント・アクセス解析は使いません。meta CSPで外部通信、インラインスクリプト、eval等を制限します。
- 配布フォルダーはビルド時に不要な旧ファイルを削除し、許可したファイル一覧をテストします。個人データは配布しません。
- 依存の既知脆弱性は公開前と更新時に `npm audit` で確認します。監査結果0件でも、未知の脆弱性がない保証にはなりません。

**GitHub Pagesは `_headers` をHTTPヘッダー設定として解釈しません。** meta CSPは適用されますが、frame-ancestorsなどHTTPヘッダー専用の制限は同等ではありません。HTTPSと実際のレスポンスは公開後に確認してください。

同じ `apple-head8.github.io` 配下のサイトは同一オリジンです。保存キーの名前を分けてもセキュリティ上の隔離にはなりません。他サイトに侵入された場合、ブラウザ内記録や保存先ハンドルが影響を受ける可能性があります。隔離するには専用ドメイン／サブドメインを使用します。

端末やブラウザ拡張の侵害、配信アカウントの乗っ取り、端末紛失をこのアプリだけで防ぐことはできません。重要な記録は別途コピーし、配信側は多要素認証と依存更新を行ってください。ホスティング側には通常のアクセスログが残る場合があります。

## 確認範囲

自動テストは、ローカル保存と再起動、30世代バックアップ、入力検証、性格補正、JSON復元、IndexedDBの競合、ファイル書き込み失敗と再試行、許可拒否、配布ファイルを対象とします。ブラウザ保存はfake-indexeddb、ファイルAPIはテストダブルによる検証を含みます。

OSのファイル選択・許可ダイアログを含む実機確認や、公開URLでの保存確認の代わりではありません。公開後はPCのChrome・Edgeで「作成→保存→再訪→同じファイルから再開」を確認してください。直接保存に未対応の環境では、JSONのダウンロードと再読み込みを確認します。スマートフォン実機の網羅的検証・侵入テスト・外部監査は未実施です。
